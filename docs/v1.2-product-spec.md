# Long Form Design Studio v1.2 — Professional Editing & Resilient Publishing Product Specification

## Purpose
v1.2 turns Long Form Design Studio from an AI-first generator into a resilient editorial-design workspace. The system must preserve A4/page-size invariants, allow human art-direction after AI generation, keep review exports available at every stage, and never sacrifice readability merely to satisfy an arbitrary page target.

## 1. Adaptive page target
### User goal
A user can request an exact target such as 60 A4 pages, but the Studio must not stop merely because one generated page cannot fit the readable A4 content budget.

### Required behaviour
- `Auto` length: Studio determines the length.
- `Exact pages` + `Allow automatic page increase` (default ON): the number is a preferred initial target. If source fidelity and readable A4 typography cannot fit, Studio automatically expands the target and continues.
- `Exact pages` + auto increase OFF: preserve the hard-stop/fallback workflow and allow manual increase/resume.
- Auto expansion never changes the physical page size. Documents remain A4 portrait 210 × 297 mm.
- Auto expansion never solves overflow by shrinking sustained body text below the Studio readability floor.
- Completed pages remain immutable during expansion. A revised plan is generated only for remaining pages.
- The event stream emits `target-expanded` with old target, new target, completed count and explanatory message.
- The final effective target is persisted in project settings and is the count used by QC.

### Acceptance criteria
1. A 60-page job that cannot fit can expand to a higher target and continue without losing completed pages.
2. User sees the new total in live generation immediately.
3. Final document count matches the final effective target.
4. If the system reaches the maximum expansion policy, saved draft recovery remains available.

## 2. Export before QC
### User goal
A creator must always be able to download the current design to inspect or share internally, even when QC has not run or has failed.

### Required behaviour
Two export classes:
- **Working / Review export** — always available as a clean artwork preview; does not invoke AI QC as a prerequisite and does not stamp QC notes onto the page.
- **Final export** — QC/approval gated.

Review exports still run deterministic/rendered preflight for diagnostics, but a failed preflight is reported rather than used as a download lock.

### Acceptance criteria
- Review Digital PDF is available with QC pending, stale, 67/100, or failed.
- Review Print PDF is also available.
- Presentation/Graphic review outputs remain available where supported.
- Final export continues to enforce QC and approval policy.

## 3. Recent work actions
Every project thumbnail includes:
- Open
- Export (Review Digital PDF)
- Delete

Delete requires confirmation and removes both server project and browser recovery copy. Export automatically restores the browser recovery copy to the server if the server record is missing.

## 4. Professional element editing
### Flow and free-position modes
Every content block has a `frame` object:
```json
{
  "freeform": false,
  "x": 6,
  "y": 12,
  "w": 88,
  "h": 18,
  "autoHeight": true,
  "z": 1
}
```
Coordinates and dimensions are percentages of the page content region, not pixels, so the design remains stable across browser zoom/export.

### User controls
- Move any paragraph, heading, stat, table, chart, image, icon/structured block using a drag handle.
- Resize width/height using a resize handle.
- Inspector provides numeric X, Y, Width and Height fields.
- Flow/Free positioning switch.
- Auto-height toggle.
- Bring forward / send backward layer control.
- Resetting to Flow restores normal editorial flow.

### Reflow rules
- Reducing text frame width rewraps text; it must not scale/stretch the font.
- Auto height grows with content.
- Fixed height is allowed but QC blocks likely clipping/overflow.
- A free-position frame may never silently extend outside the safe page content region.

## 5. Semantic page surfaces
Pages do not need to be white, but decoration must communicate role rather than become a repeated motif.

Available semantic surface modes:
- Plain
- Top band
- Side panel
- Data band
- Quote panel
- Split tint
- Chapter field
- Soft grid
- Dark

### Automatic art direction
The AI/layout intelligence selects surfaces deterministically from page role:
- cover/chapter: stronger chapter field
- data/stat/table/chart: restrained analytical bands
- quote: quote panel
- image-led: split tint
- process/timeline: side panel
- closing: dark
- ordinary narrative: usually plain

The same decorative pattern must not be stamped across all pages. Page-to-page variation is driven by meaning and narrative rhythm while colours remain within the active Recykal/project palette.

### Manual control
Editor Page controls allow the user to override the surface mode for a page.

## 6. A4 invariants
For Documents:
- Physical page size is fixed A4 portrait 210 × 297 mm.
- Two-column mode changes internal grid only; page height cannot grow.
- Overlong content continues to a new A4 page.
- Tables repeat headers when they continue.
- Wide tables split into readable column groups rather than shrinking to unreadable type.

## 7. QC additions
QC must flag/block:
- free-position frames outside page bounds
- likely clipping in fixed-height frames
- excessively narrow long-text frames
- body typography below the readability floor
- malformed/inconsistent tables
- physical A4 overflow
- repeated layouts/surfaces that weaken long-form rhythm

## 8. Persistence and paid-AI safety
- Postgres remains source of truth.
- Browser IndexedDB is secondary safety vault.
- Page-safe generation checkpoints each completed page.
- Page-target expansion checkpoints the project before continuing.
- Review export can restore a missing server project from Browser Safety Vault.

## 9. Non-goals / guardrails
- Manual element freedom must not change the Recykal logo artwork, proportions, or brand font rule.
- The Studio must not invent source facts merely to fill space.
- The Studio must not use visual decoration as a substitute for information structure.
- Generative design quality cannot be mathematically guaranteed; deterministic constraints and production invariants are enforceable and must be validated.
