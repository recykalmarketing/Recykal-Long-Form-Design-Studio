# v1.2.3 — Durable Resume, Source Integrity & Cost Control

This release addresses interrupted long-form generations that previously stopped mid-document and could not continue after reopening the project.

## Recovery architecture

- Every completed page is durably checkpointed before the next page begins.
- Generation state now records `phase`, `completed`, `total`, the persisted design plan, and a per-page source integrity ledger.
- Cancelling or aborting a generation marks it `paused` rather than destroying the completed work.
- Reopening a paused/failed/running incomplete document shows **Continue from checkpoint**.
- Resume uses the original/saved final page target by default. Increasing the page count is optional, not required.
- Resume reconstructs deterministic source allocation from the attached source and does not regenerate already completed pages.
- If all pages were generated but final layout/visual/QC processing stopped, Resume skips page generation and continues only the finalization stages.
- OpenAI page calls have a bounded timeout so the UI does not remain indefinitely on “working on page N”.

## Preserve-mode source integrity

- PDF extraction is geometry-aware: lines are reconstructed by page coordinates rather than naïve text concatenation.
- Common PDF ligatures and broken `fi` / `fl` word fragments are normalized.
- Large horizontal gaps are preserved as column boundaries, improving glossary, table and contents-page reconstruction.
- Each preserve-mode page is validated against its assigned authoritative source slice.
- Required per-page gate: >=99.5% source-token coverage and >=98.5% ordered alignment. Failed AI layouts fall back to a deterministic source-faithful page rather than silently dropping content.
- The final document has the same whole-document source coverage/order gate before final export.
- TOC and glossary fallback pages use table structures when column data can be recovered.

## Pagination behavior

- Exact A4 targets no longer auto-expand unless the user explicitly enables that option.
- Resume can continue at the same saved page target.
- All completed pages are immutable during resume.
- A finalization checkpoint is written before layout, visuals and QC so a late-stage failure can resume without paying for page generation again.

## OpenAI usage reduction

- Stable layout/QC prompts use a prompt-cache key.
- Page generation is page-scoped and only unfinished pages are called again after a failure.
- Automatic focal-point vision analysis is disabled by default; center-crop is used unless `AUTO_ANALYZE_FOCAL_POINT=true` is intentionally enabled.
- Image variations remain 1 by default and `AUTO_IMAGE_LIMIT` can cap automatic raster image calls.
- Structural source fidelity, pagination, TOC/glossary detection and source coverage are deterministic and do not consume model calls.

## Production environment

Recommended variables:

- `OPENAI_PAGE_TIMEOUT_MS=120000`
- `OPENAI_PROMPT_CACHE_KEY=lfds-v1.2.3-layout-engine`
- `AUTO_ANALYZE_FOCAL_POINT=false`
- `REQUIRE_DURABLE_STORAGE=true`
- `DATABASE_URL=<Render Postgres connection>`

Do not deploy paid long-form generation without durable database storage.
